# 实验结果解读

这份首次实验对应提交 `117da42`。后续代码问题、修复和逐请求数据拆解见 [审查报告](audit.md)；本文件的历史性能数值不代表修复后的代码。

本次为 seed=42 的一次完整三组对照；每组正式窗口有 8,998,486 个请求，200 秒预热后统计 600 秒。全部积压门限、输入指纹和流量校验通过，共同时间比例为 1。

| 模型 | 累计配置 RTT 均值 ms | 真实进程/IPC 耗时均值 ms | 前台回源 | 预取回源 | 总回源 |
| --- | ---: | ---: | ---: | ---: | ---: |
| baseline | 19.092933 | 0.523786 | 1,538,534 | 0 | 1,538,534 |
| ReDNS | 13.056151 | 0.755228 | 1,020,304 | 0 | 1,020,304 |
| ReDNS-prefetch | 12.618206 | 1.255210 | 983,388 | 83,539 | 1,066,927 |

相对无预取 ReDNS，预取版的累计配置 RTT 均值降低 **3.354%**，前台回源减少 **36,916 次（3.618%）**。新增的 83,539 次预取回源超过前台回源减少量，因此总回源增加 **46,623 次（4.570%）**。

真实进程/IPC 耗时均值由 0.755228 ms 增至 1.255210 ms，增加约 66.2%。这个指标包含队列、进程执行和操作系统调度，不能由上述一次试验确定各因素的贡献。累计配置 RTT 没有包含这部分开销，模拟器也没有模拟后台流量的带宽竞争与网络排队；因此不能据此推断真实部署中的端到端时延一定降低。

三组 p95 累计配置 RTT 分别为 111、112、112 ms；本次预取改善均值，没有改善该分位数。正式阶段预取落点缓存接受 83,539 条，其中 33,928 条在观察结束前被实际查询使用；这不是完整的预取浪费率，既不包括转存后的使用，也不能把结束时仍有效但未使用的记录直接判为浪费。

本次对照测量的是预取和低负载候选调度的组合效果。没有额外运行“只改变候选排序”的消融组，也没有多个 seed 的重复试验，所以不声称单独预取因素的因果贡献或统计显著性。算法参考 Forestall 的预测与过滤思路，工程适配差异见 [PREFETCH.md](../../PREFETCH.md)。

完整配置、指纹、时序和统计摘要见 [summary.json](summary.json)，自动生成的结果表见 [report.md](report.md)。大结果位于 `res/prefetch/`，包括三份逐请求结果、manifest 和本次运行日志。
